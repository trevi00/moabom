**1) `infra/nginx/default.conf`** — 아래를 그대로 쓴다.

핵심 설계 결정 2가지:
- **`alias`가 아니라 `root`를 쓴다.** 미디어를 `/srv/media`에 마운트하고 `root /srv;`로 두면 `/media/x.m3u8` → `/srv/media/x.m3u8`로 자연 매핑된다. `alias` + 정규식 location 조합은 경로가 이중으로 붙어 깨지고, 경로 순회 표면도 넓힌다.
- **`sendfile off;`** — Windows 바인드 마운트(가상화 파일시스템)에서 `sendfile`이 **잘린/낡은 파일**을 내보내는 사례가 보고돼 있다. "가끔 세그먼트가 깨진다"로 나타나 트랜스코딩 버그로 오진하기 딱 좋다(CP-11). P2에서 실 세그먼트가 생기기 전에 넣어두면 비용 0.

```nginx
server {
    listen 80;
    server_name _;
    charset utf-8;

    # CP-11: Windows 바인드 마운트에서 sendfile 이 잘린/낡은 파일을 내보내는 사례가 보고됐다.
    #        "가끔 세그먼트가 깨진다" 로 나타나 트랜스코딩 버그로 오진하기 쉽다. 비용 0 이므로 선제 차단.
    sendfile off;

    # 미디어 루트는 /srv/media 에 :ro 로 마운트된다 (compose.yaml).
    # alias 가 아니라 root 를 쓴다 — 정규식 location 과 경로가 이중으로 붙지 않고 순회 표면도 없다.
    root /srv;

    # PITFALLS Pitfall 4: 플레이리스트와 세그먼트의 캐시 수명을 분리한다.
    # 재트랜스코딩/렌디션 추가 시 낡은 마스터 플레이리스트가 삭제된 세그먼트를 요청하면
    # 404 -> hls.js fatal NETWORK_ERROR 로 끝난다. (실검증은 P2 소관)
    location ~* ^/media/.+\.m3u8$ {
        default_type application/vnd.apple.mpegurl;
        add_header Cache-Control "public, max-age=10" always;
    }

    location ~* ^/media/.+\.(ts|m4s|mp4|vtt)$ {
        add_header Cache-Control "public, max-age=31536000, immutable" always;
    }

    location /media/ {
        autoindex off;
        try_files $uri =404;
    }

    location = /healthz {
        access_log off;
        add_header Content-Type text/plain;
        return 200 "ok\n";
    }

    location / { return 404; }
}
```
