**`docs/adr/0001-runtime-versions.md`** — 아래 요소를 **전부** 포함한다:

1. **Status**: Accepted (2026-08-06)
2. **Context**: 로컬/도커 전용 포트폴리오. 회사 스택(Java 17 + MySQL) 정합성 + Spring Modulith 학습 목표.
3. **Decision — 버전 핀 표** (build.gradle·compose.yaml과 값이 일치해야 한다):
   - JDK Temurin **17** (Boot 3.2 baseline)
   - Spring Boot **3.2.12** — 3.2 라인 **최종 패치**
   - Spring Modulith **1.1.12** (공식 매트릭스 3.2.x ↔ 1.1.x)
   - Gradle **8.14.5** (Boot 3.2 플러그인은 "7.x(7.5+) 또는 8.x" 지원 — 9.x는 목록 밖)
   - MySQL **8.0** / Flyway 9.22.3 + `flyway-mysql`
   - resilience4j-spring-boot3 **2.2.0**
   - 이미지: `nginx:stable-alpine` · `prom/prometheus:v3.13.2` · `grafana/grafana:13.1.2` · `node:24-alpine`
4. **EOL 인지·수용 (G1의 핵심)**:
   - Spring Boot 3.2 **OSS 지원 종료 2024-12-31**, 마지막 패치가 3.2.12다. **새 CVE가 3.2 라인에 나오면 백포트가 영영 없다.**
   - MySQL 8.0 **Extended Support 2026-04-30 종료**. `mysql:8.0` 태그는 2026-05-05 갱신 이후 사실상 동결됐다(pull은 계속 가능).
   - **왜 그래도 수용하는가**: 인터넷 미노출(로컬 compose 네트워크 + 루프백 바인드), 민감 데이터 0, 포트폴리오 수명 내 운영 리스크 낮음.
   - **승격 경로**: Boot 3.3+로 이동 시 Modulith도 1.2+로 **동반 이동**해야 한다(단독 bump 금지). MySQL은 8.4 LTS.
5. **non-blocking CVE 스캔 — 선택 근거 (G1)**:
   - **Dependabot 채택.** CI 상태에 영향이 없어 **태생적으로 non-blocking**이다. Trivy/OWASP는 `continue-on-error: true`가 필요하고, 그걸 잊으면 blocking이 된다.
   - **blocking CVE 게이트를 두지 않는 이유**: EOL 라인이라 게이트가 상시 붉다. **붉은 CI 방치가 신호 자체를 죽인다.** 가시성을 유지하는 것이 목표이고 차단이 목표가 아니다.
   - `.github/dependabot.yml`의 `ignore:` 규칙이 **이 결정을 코드로 표현한 것**임을 명시하고 파일을 링크한다.
6. **resilience4j 2.2.0 핀 — 3중 방어**: (a) `build.gradle`의 `resolutionStrategy.force`(실 강제), (b) Dependabot `ignore`(PR 자체를 안 열게), (c) CI `dependencyInsight` 게이트(가시성). 근거: 2.3.0은 Boot 3 + Java 17에서 **기동 단계에서 죽는다**(resilience4j issue #2265).
7. **SC1 정직 재서술**: "한 커맨드 기동"은 **이미지 선행 빌드 1회 + `docker compose --profile full up`**이다. compose는 Gradle을 실행할 수 없다. `pull_policy: never`가 이미지 부재를 즉시·명확히 실패시킨다.
8. **bootBuildImage 빌더 기록 (CP-3 A5 완화)**: Boot 3.2.12의 기본 빌더는 `paketobuildpacks/builder-jammy-base:latest`다. `:latest` 태그는 재현성이 없으므로 아래 줄을 넣어 두고 **Plan 07이 첫 성공 빌드 후 실측 다이제스트를 채운다**:
   ```
   - builder image: paketobuildpacks/builder-jammy-base:latest
   - first successful build digest: (Plan 07 실기동 태스크가 기록)
   ```
9. **위협모델 accept 항목 명시**: MySQL root 기본 비밀번호(`moabom-local`)는 로컬 전용 값이며 실 시크릿과 구분된다. `app:8080`만 `0.0.0.0` 바인드인 이유(prometheus host-gateway 스크레이프)와 그 잔여 위험.
10. **D-00 진화 서사**: Modulith 모듈리스로 시작하고, 물리 MSA·Redis·DB 읽기 복제본은 **부하를 주입해 병목을 실측한 뒤** 증설한다(M1 후반 phase 9~). Phase 1은 이를 선반영하지 않는다.

**`docs/adr/0002-media-and-encoding.md`** — 아래 요소를 **전부** 포함한다:

1. **Status**: Accepted (2026-08-06)
2. **미디어 격리 4중 방어와 각 층의 실제 강도**:
   - 1차: 미디어 루트가 **저장소 밖** `D:/moabom-media/` — 물리적으로 git이 볼 수 없으면 사고가 불가능하다
   - 2차: `.gitignore` 경로 스코프 패턴
   - 3차: `.githooks/pre-commit` 확장자 + 5MB 게이트 — **`--no-verify`로 우회 가능. defense-in-depth이지 boundary가 아니다**
   - 4차(**실 boundary**): CI의 `git rev-list --objects --all` 히스토리 전체 스캔
   - **`.gitignore`에 전역 `*.ts`를 쓰지 않는 이유**: `.ts`는 MPEG-TS 세그먼트이자 TypeScript다. `frontend/`가 같은 저장소에 살므로 전역 배제는 Next 소스를 통째로 삼킨다. 대체 = 경로 스코프 + 5MB 크기 게이트. CI가 `git check-ignore frontend/next.config.ts`가 **매칭되지 않음**을 회귀 게이트로 지킨다.
   - 5MB 임계값 근거: GitHub 하드 리젝은 100MB지만, 회복 비용이 비대칭이라 훨씬 앞에서 끊는다. HLS 세그먼트는 개별로는 작아도 수백 개다 → 확장자/경로 규칙이 크기 게이트를 보완한다.
3. **Windows 파일명 ASCII-safe 정책 (G4)**:
   - **규칙**: 파일시스템에 쓰이는 산출물 경로(트랜스코딩 결과·HLS 세그먼트·디렉터리명)는 `[A-Za-z0-9._-]`만 사용한다. 원본의 한글·공백·괄호·`#` 등은 **DB 메타데이터(`title.title_ko`)로만 보존**하고 경로에는 ASCII slug를 쓴다.
   - **근거**: Windows 로케일에서 ffmpeg/ProcessBuilder에 넘기는 인자가 cp949로 인코딩돼 파일을 못 찾는 사고가 장편에서 확실히 걸린다(짧은 클립에서는 재현 안 됨). P2·P8이 이 정책의 소비자다.
4. **UTF-8 명시 지점 목록 (G4 — 각각이 실제 파일에 있어야 한다)**:
   - `.editorconfig`: `charset = utf-8`
   - `backend/build.gradle`: `options.encoding = 'UTF-8'` + test `systemProperty 'file.encoding'/'sun.jnu.encoding'`
   - `backend/gradle.properties`: `org.gradle.jvmargs=... -Dfile.encoding=UTF-8`
   - `compose.yaml` app 서비스: `JAVA_TOOL_OPTIONS: "-Dfile.encoding=UTF-8 -Dsun.jnu.encoding=UTF-8"`
   - MySQL: `--character-set-server=utf8mb4 --collation-server=utf8mb4_0900_ai_ci` + JDBC `characterEncoding=UTF-8`
   - `.gitattributes`: `* text=auto eol=lf` (+ `gradlew` lf / `*.bat` crlf)
5. **D-14 규율 (이 문서가 D-14의 산출물이다)**:
   - `event_publication` 테이블은 **Flyway가 소유**한다. Modulith의 자동 스키마 생성을 쓰지 않는다: `spring.modulith.events.jdbc.schema-initialization.enabled: false`를 `application.yaml`에 명시했다.
   - `spring-modulith-starter-jpa`는 **`@ApplicationModuleListener` 첫 사용 phase(P3 예상)에서 해당 V 마이그레이션과 같은 커밋**에 추가한다. 먼저 넣으면 `JpaEventPublication` @Entity가 `ddl-auto=validate`와 충돌해 기동이 죽는다.
   - ⚠️ 정직 표기: Modulith 1.1.x의 이벤트 프로퍼티 키 이름은 버전 간 변경 이력이 있다 — P3 착수 시 실측 재확인 대상이다.
6. **P1 의존성 델타 이월 기록 (CP-7)**: `spring-boot-starter-security` / `spring-session-jdbc` / `springdoc-openapi` 는 P1에서 **의도적으로 제외**했다. 특히 security 스타터는 기본 체인이 전 경로에 HTTP Basic을 걸어 `/api/health`가 401이 되고, D-02의 실동작 검증이 불가해진다. 임시 `permitAll` 체인은 P3에서 지워야 할 죽은 설정이 되므로 만들지 않는다. **소비자(AUTH-01/02)가 생기는 Phase 3에서 함께 들어온다.**
7. **nginx 운영 규약**: 미디어 마운트는 `:ro`(쓰기 주체는 ingest P8뿐). `sendfile off`(Windows 바인드 마운트의 잘린 파일 사고). m3u8 `max-age=10` / 세그먼트 `immutable` 캐시 분리(실검증은 P2).
