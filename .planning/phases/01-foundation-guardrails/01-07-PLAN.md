**프로브 1 — V-SC2d: 모듈 경계 위반이 verify()를 실제로 죽이는가**

`catalog`는 `allowedDependencies = {}`이므로 다른 어떤 모듈에도 의존할 수 없다. 임시 파일로 위반을 만든다:

```bash
cd /d/moabom/backend
cat > src/main/java/com/moabom/catalog/BoundaryProbe.java <<'JAVA'
package com.moabom.catalog;

// V-SC2d 반사실 프로브 — catalog(allowedDependencies={})가 playback::spi 를 참조한다.
// verify() 가 이것을 잡지 못하면 SC2 의 문장이 거짓이다. 확인 후 즉시 삭제한다.
import com.moabom.playback.spi.WatchHistoryPort;

class BoundaryProbe {
    WatchHistoryPort port;
}
JAVA

./gradlew test --tests "*ModularityTests*" --no-daemon
echo "EXIT=$?"      # 반드시 0 이 아니어야 한다
```
출력에서 **위반을 지목하는 실제 문자열**을 그대로 복사해 로그에 인용한다(예: `Module 'catalog' depends on module 'playback'` 형태). 그다음 원복:
```bash
rm src/main/java/com/moabom/catalog/BoundaryProbe.java
./gradlew test --tests "*ModularityTests*" --no-daemon
echo "EXIT=$?"      # 반드시 0
```

⚠️ **`./gradlew test`가 exit 0으로 통과해버리면 그것이 결함이다.** 프로브를 지우고 넘어가지 말고, 원인을 확인한다:
- `catalog/package-info.java`에 `@ApplicationModule` 선언이 실제로 있는가
- `ModularityTests.verifiesModularStructure`가 `modules.verify()`를 호출하는가
- 컴파일 실패로 테스트가 아예 안 돈 것은 아닌가(이 경우도 CI는 붉어지므로 게이트 자체는 유효 — 로그에 그 사실을 정직하게 구분해 기록)
